# PetCare+ Design System

PetCare+ 화면을 수정하거나 새 화면을 만들 때 따르는 디자인 기준입니다.

## 디자인 원칙

- 모바일 앱처럼 즉시 사용할 수 있는 화면을 우선한다.
- 랜딩 페이지식 설명보다 실제 기록, 조회, 편집 UI를 우선한다.
- 조용하고 신뢰감 있는 건강 관리 앱 톤을 유지한다.
- 과도한 장식보다 읽기 쉬운 정보 구조와 반복 사용성을 우선한다.
- 의료 진단처럼 보이는 표현은 피하고 보호자 기록 정리 도구의 언어를 사용한다.

## 앱 프레임

- 기본 앱 프레임은 `.app`을 사용한다.
- 모바일 최대 폭은 기존 `430px` 기준을 유지한다.
- 데스크톱에서는 모바일 프레임이 중앙에 놓이는 구조를 유지한다.
- 세로 스크롤 영역은 `.scroll`을 사용한다.
- 하단 탭바 또는 고정 버튼이 있는 화면은 하단 padding과 safe-area를 반드시 확인한다.

## 색상

- 기본 색상 토큰은 `css/style.css`의 `:root`를 따른다.
- 주요 브랜드 색상은 `--color-primary` 계열을 사용한다.
- 병원, 약, 증상, 사진 등 유형별 색상은 기존 `--c-*` 토큰을 우선 사용한다.
- 새 색상이 필요하면 기존 색상 계열과 대비, 의미가 겹치지 않는지 확인한다.
- 한 화면이 하나의 색상 계열로만 보이지 않게 한다.

## 타이포그래피

- 기본 폰트는 Pretendard 계열을 유지한다.
- 화면 제목은 기존 `.pv2-title`, `.pv2-nav-title` 크기와 굵기를 따른다.
- 카드 내부 제목은 과도하게 크게 만들지 않는다.
- 버튼, 칩, 탭바 텍스트는 모바일에서 줄바꿈 또는 잘림이 없도록 확인한다.
- viewport 폭에 따라 font-size를 직접 스케일링하지 않는다.

## 레이아웃

- v2 화면의 헤더와 탭바는 `css/page-v2.css` 기준을 따른다.
- 화면 좌우 기본 여백은 `.app .scroll`의 `16px` 흐름을 우선한다.
- 카드 내부 padding과 카드 사이 간격은 기존 화면과 유사하게 유지한다.
- 카드 안에 또 다른 카드처럼 보이는 중첩 구조는 피한다.
- 고정 하단 버튼이 있는 화면은 콘텐츠가 버튼 뒤에 숨지 않도록 별도 bottom padding을 둔다.

## 컴포넌트

- 헤더: `.pv2-header`, `.pv2-header-nav`, `.pv2-header-actions`
- 아이콘 버튼: `.pv2-icon-btn`
- 하단 탭바: `.pv2-tabbar`, `.pv2-tab`
- 기본 버튼: `.btn`, `.btn-primary`, `.btn-ghost`, `.btn-block`
- 입력: `.input`, `.textarea`, `.form-group`, `.form-label`
- 시트: `.sheet-overlay`, `.sheet`, `.sheet-title`
- 병원 화면: `.hosp-*`

## 병원 화면 기준

- 병원 기록 목록, 추가, 상세 화면은 `css/hospital.css`에 스타일을 둔다.
- 병원 추가 폼 섹션은 `.hosp-form-section`을 사용한다.
- 폼 섹션은 `.scroll`의 기본 좌우 padding과 중복되는 마진을 만들지 않는다.
- 검사 자료, 처방, 다음 진료 정보는 기존 카드/칩/시트 패턴을 재사용한다.

## 접근성과 사용성

- 아이콘만 있는 버튼은 `aria-label`을 둔다.
- 입력 필드는 라벨과 placeholder 역할을 명확히 구분한다.
- destructive action은 확인 절차를 둔다.
- 모바일 터치 영역은 너무 작지 않게 한다.
- 모달과 시트는 배경 클릭 닫힘, 닫기 버튼, 저장 버튼 상태를 확인한다.
